## 测试邮件发送失败（TLS 帧错误）排查与修复

- 现象：后台「服务器配置」发测试邮件报 `Cannot determine the frame size or a corrupted frame was received.`
- 根因：数据库 `ServerSettings` 行里是 `smtp.yeah.net:25` + 隐式 TLS 开启；25 是明文 SMTP，
  SslStream 把服务器 `220` 欢迎语当 TLS 记录解析。实测 yeah.net：25 明文、465 隐式 TLS(TLSv1.3)、587 不通。
- 配置优先级：`appsettings.json` 的 Email 段只在首次播种时用，之后以数据库为准，
  环境变量 `Email__*` 又优先于数据库；所以改 appsettings 的 465 不生效。
  本地运行实例是 7788 上的 `SpServer.exe`，Vite 5174 代理到 7788。
- 处置：`PUT /api/admin/server` 把端口改为 465（隐式 TLS 保持开），即时生效；
  `POST /api/admin/server/test-email` 返回 200，测试邮件成功发到配置邮箱。
- 代码防护：`EmailSender.ValidateTlsMode` 发信前拦截 25/587+隐式TLS、465+非隐式TLS 组合；
  `ServerConfig.SaveAsync` 保存时同样校验并返回 `smtp_tls_mismatch`；TLS 握手异常包装成中文提示；
  EHLO 能力检查（未声明 STARTTLS 时提示改 465）；后台表单加端口/开关联动校验。
- 验证：dotnet build 0 警告 0 错误、admin `npm run build` 通过；隔离实例（7799 + 环境变量强制 25/隐式TLS）
  复现出 400 与 502 的可操作中文报错，不再出现 frame size。
- 待办：7788 上仍是旧二进制，新防护代码需重启/重新发布后生效；
  `server/appsettings.json` 被 git 跟踪且含明文 SMTP 授权码与 Admin.Key（当前未提交），
  提交前应改成环境变量或后台加密存储并轮换。

## 注册验证码没发到邮箱

- 关键发现：打包扩展 `deploy/dist/extension-0.1.0` 的默认后端是线上 `http://43.142.147.244:7788`，
  本地 `edge/` 默认 `http://127.0.0.1:5080`（当前无监听）；本地 7788 的 EmailCodes 当时为空，
  说明注册请求根本没打到本地，而是打到线上。
- 线上 SMTP 原配置：`smtp.yeah.net:25` + 关闭隐式 TLS + **passwordSet=false**（无授权码），
  后台却显示 `configured:true`。云服务器出站 25 被封导致 20s 超时，
  超时是 OperationCanceledException，被调用方 catch 排除 → HTTP 500 空响应；本机模拟 25+STARTTLS
  用空密码得到 `535 authentication failed`。
- 处置：通过线上 `PUT /api/admin/server` 改成 465 + 隐式 TLS + 写入授权码，
  线上 test-email 与 `/api/auth/email-code` 均返回 200（devCode 为 null，说明已提交 SMTP）。
- 代码加固（`EmailSender.cs` / `ServerConfig.cs` / 后台 UI / 扩展提示）：
  超时转成中文 IOException（不再 500 空响应、验证码记录能正确回滚）；
  填了账号没密码时提前报错；`EmailSettingsView` 新增 `warning`，后台显示橙条；
  邮件补 Message-ID / Reply-To / X-Mailer / Auto-Submitted 降低进垃圾箱概率；
  验证码提交成功记日志；扩展提示带上收件邮箱。
